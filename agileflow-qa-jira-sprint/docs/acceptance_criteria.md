# Acceptance Criteria - Sprint 7

## PROJ-2: Create and Manage Test Cases

**As a QA, I want to create and manage test cases linked to user stories**

### Acceptance Criteria
1. User can create a new test case with Title, Preconditions, Steps, and Expected Result.
2. Test case can be linked to one or more user stories.
3. User can edit and delete existing test cases.
4. Test cases appear in a searchable list filtered by story.
5. Only users with QA role can create/edit test cases.

---

## PROJ-3: Execute Test Cases

**As a QA, I want to execute test cases and record results during sprint**

### Acceptance Criteria
1. Tester can open a test case and mark it as Pass / Fail / Blocked.
2. System records execution date, tester name, and comments.
3. Execution history is visible for each test case.
4. Failed test cases offer a quick “Log Defect” option.
5. Test execution status is reflected on the Kanban board.

---

## PROJ-4: Burndown Chart for QA Tasks

**As a Scrum Master, I want a burndown chart for QA tasks**

### Acceptance Criteria
1. Burndown chart displays remaining story points vs. ideal line.
2. Chart updates daily based on completed tasks.
3. Chart can be filtered by Epic or by QA-related labels.
4. Chart is visible on the Sprint Board and Reports section.

---

## PROJ-5: Defect Tracking

**As a team, I want to log and track defects with severity levels**

### Acceptance Criteria
1. User can create a bug with Summary, Description, Severity, and Steps to Reproduce.
2. Severity levels available: Critical, High, Medium, Low.
3. Bugs can be linked to test cases and user stories.
4. Bugs appear on the Kanban board under “In Testing / QA” or “To Do”.
5. Users can attach screenshots or logs to bugs.
